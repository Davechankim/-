# 구현 가능성 검증 — 백라인(가칭) 소개 사이트의 약속들

기준일 2026-10-11. 사이트(`backline/index.html`)가 약속하는 기능을 하나씩 "지금 실제로 만들 수 있는가"로 검증했습니다.
판정은 넷입니다. **가능** · **조건부**(구조를 바꾸거나 심사·제휴가 필요) · **반자동**(기계가 준비하고 사람이 마지막 한 번을 누름) · **불가**(제휴 없이는 할 수 없음).
근거는 웹 검색으로 확인한 공개 자료입니다. 이 작업 환경에서는 당근·번개장터·뮬·메타·네이버의 문서 페이지를 직접 열 수 없어, 약관 원문이 필요한 항목은 마지막 장에 "직접 확인 목록"으로 따로 적었습니다.

핵심 결론: **"모든 장터를 한 화면에, 한 번 등록으로 모든 곳에"는 지금 한국에서 법적·기술적으로 절반만 가능하고, 그 절반도 제휴와 심사에 달려 있습니다. 반면 검수·출장 리페어·장비 이력부·안전결제는 전부 우리 손 안에 있습니다.** 투자 소개의 무게 중심을 후자로 옮기고, 통합 검색·동시 게시는 "허용된 채널부터, 나머지는 반자동"으로 정직하게 쓰는 것을 권합니다.

## 1. 통합 검색 (채널별)

### 통앤통 (네이버 카페)
- 네이버는 2026-09-07(개발자센터)·09-20(NAVER API HUB) 시행 검색 API 특약으로 **카페 글을 자동 수집해 외부 서비스에 노출하는 행위를 막고**, 검색 API로 받은 데이터의 **복사·저장·캐싱(기기 24시간, 서버 이력 21일 예외)·제3자 제공·AI 입력·가공 노출·순위 변경·결과 페이지 광고·API 수익화를 금지**했습니다. 쇼핑·책·학술 검색 API는 2026-07-31 종료, 검색 API는 NAVER API HUB로 이관 중이며 종량제 과금 예정입니다.
- 따라서 가능한 형태는 하나뿐입니다. **"네이버 카페글 검색" 블록을 우리 검색 결과와 섞지 않고, 가공 없이, 그대로 보여주고 원문으로 보내는 것.** 우리 매물과 한 목록으로 정렬하는 "한 화면 통합"은 약관상 불가합니다. 저장도 못 하므로 시세 산출·알림·AI 요약에도 못 씁니다.
- 로그인 뒤 카페 페이지를 긁는 방식은 약관 위반이자 정보통신망법(접근권한 초과) 위험이 있어 제외합니다.
- 판정: **조건부(분리 블록 표시만)**. 특약 원문과 카페글 API의 월 호출 한도·단가는 API HUB 콘솔에서 직접 확인 필요.

### 당근
- 매물 조회용 공개 API가 확인되지 않습니다. 법률 해설은 당근 약관이 회사가 안내한 방법 외의 접근을 제한한다고 설명하고, 시중의 스크레이퍼는 당근 내부 JSON 로더를 읽는 비공식 방식입니다.
- 판정: **제휴 없이는 불가**. 당근이 제휴할 가능성도 낮으므로 "당근 바로가기"로 두는 것이 현실적입니다.

### 번개장터 · 뮬
- 둘 다 공식 API가 확인되지 않습니다. 번개장터는 공개 JSON을 읽는 서드파티 도구가 있으나 약관상 허용 여부는 미확인. 뮬은 자체 앱에 키워드 알림 기능을 두고 있어 장터 데이터를 자산으로 보는 사업자입니다.
- 판정: **제휴 전까지 불가**. 뮬은 규모가 작아 데이터 제휴 협상이 가능할 수 있습니다. 악기 전문 커뮤니티라 '뮬 매물 바로가기 + 뮬 판매자 인증 리페어맨 연결' 같은 상호 이익 제안이 현실적입니다.

### 인스타그램
- 공식 Hashtag Search API로 특정 해시태그의 최근·인기 게시물을 가져올 수 있으나, **비즈니스/크리에이터 계정당 7일 동안 고유 해시태그 30개** 제한, App Review(Instagram Public Content Access) 필요, 이모지 검색 불가, 가져온 게시물에 댓글 불가입니다.
- 판정: **조건부(소규모)**. `#중고기타 #기타판매 #이펙터판매` 같은 핵심 태그 30개로 "인스타 매물 보기" 블록을 만드는 것은 가능하지만 전체 커버는 못 합니다. 메타 플랫폼 약관의 데이터 보관 제한도 확인 필요.

### 네이버 스마트스토어
- 상품 검색용 공개 API가 없습니다(네이버 쇼핑 검색 API는 2026-07-31 종료). 가능한 것은 **제휴 샵이 커머스API로 자기 스토어를 연결하는 것**이며, 제3자 솔루션은 네이버 **커머스솔루션마켓 등록 또는 API대행사 자격**이 있어야 합니다(판매자용 '내스토어 애플리케이션'을 위탁받아 운영하는 것은 금지).
- 판정: **조건부(제휴 샵만, 네이버 심사)**.

### 개인 거래 · 샵 재고
- 우리 플랫폼에 등록된 매물과 제휴 샵 재고는 완전히 가능합니다. 사용자가 자기 매물 링크를 붙여 넣으면 OG 메타데이터를 읽어 "내 매물 가져오기"를 하는 방식은 동의 기반이라 위험이 낮습니다(로그인 뒤에 있는 카페 글은 안 읽힘).
- 판정: **가능**.

### 크롤링의 법적 위험 (왜 "그냥 긁으면" 안 되는가)
- 야놀자 대 여기어때: 대법원은 정보통신망법 위반·업무방해·저작권법 위반 **형사 혐의를 모두 무죄**로 확정했지만, 민사 1심(서울중앙지법)은 **부정경쟁방지법 제2조 제1호 (카)목(성과 무단 사용)으로 10억 원 배상**을 명했습니다. 잡코리아 대 사람인에서는 데이터베이스 제작자 권리가 인정됐습니다. 즉 공개 페이지를 로그인 없이 긁는 것은 형사 처벌을 받기 어렵지만, **경쟁 사업에 쓰면 민사 책임이 현실적**입니다. 2022년 신설된 데이터 부정사용 조항(파목)도 있습니다.
- 결론: 무단 수집으로 "통합 검색"을 만드는 것은 사업 리스크입니다. 동의(제휴·사용자 링크)와 공식 API만 씁니다.

## 2. 위탁 등록 → 동시 게시 → 동시 내리기 (채널별)

| 채널 | 자동 게시 | 자동 수정·내리기 | 비고 |
|---|---|---|---|
| 우리 장터 | 가능 | 가능 | — |
| 인스타그램 | **가능** (비즈니스/크리에이터 계정, OAuth 연결, `instagram_content_publish` 권한 + App Review, 계정당 24시간 50건, 캐러셀은 1건) | **캡션 수정 불가**(Updating은 댓글 허용 여부만). 삭제는 공식 문서상 미지원으로 보임(원문 미확인) → 자기 게시물에 '판매완료' 댓글 달기(댓글 생성·삭제는 가능)로 대체 | 개인 계정은 API 게시 불가 → 판매자가 계정을 전환해야 함 |
| 스마트스토어 | 가능 (커머스API: 상품 등록·수정·판매중지) | 가능 | 제3자 솔루션은 커머스솔루션마켓/API대행사 자격 필요. 개인 중고 판매자보다 샵에 해당 |

| 당근 | **반자동** | 반자동 | 공개 API 없음. 앱에서 직접 게시 |
| 번개장터 | **반자동** | 반자동 | 공개 API 없음 |
| 뮬 | **반자동** | 반자동 | 공개 API 없음. 제휴 시 재검토 |

- 반자동의 실제 모습: 한 번 입력 → 채널별 양식(제목 규칙, 가격 표기, 거래 방식, 사진 순서)에 맞춘 글과 사진 세트를 생성 → "복사" 한 번 → 해당 앱에서 붙여넣기. 등록 완료 여부는 사용자가 링크를 붙여 넣어 알려주면 이력부에 기록. 팔리면 모든 채널의 "내리기 할 일"을 푸시로 보냄.
- 중복 판매 위험: 여러 곳에 동시에 올리면 두 곳에서 동시에 팔릴 수 있습니다. "먼저 결제된 곳 기준으로 나머지는 즉시 '판매중' 표시"가 필요하며, 외부 채널은 반자동이라 몇 분의 공백이 생깁니다. 안내 문구가 필요합니다.
- 판정: **반자동**. 사이트의 "모든 채널에 한 번에 올라가고 … 한 번에 내립니다"는 **그대로 두면 과장**입니다.

## 3. 검수·보증

- 검수 자체: 인증 리페어맨이 공개된 검수 항목(넥 휨·릴리프, 트러스로드 여유, 프렛 잔량, 너트·새들, 전장 측정값(픽업 저항·포트·잭 노이즈), 바디 크랙·리피니시 흔적, 하드웨어, 시리얼·연식 대조)을 사진·수치로 기록하는 것은 **운영 설계 문제**이며 선례가 있습니다(크림의 검수 기준 공개, 번개장터의 정품검수 서비스).
- "보증 매물은 반품·수리를 보증": 금융위원회는 2015년 국정감사에서 **제조·판매사가 제공하면 부가서비스, 제3자가 제공하면 보험상품**으로 본다는 입장을 밝혔고, 보험으로 분류되면 보험회사만 팔 수 있습니다. 롯데손보가 EW(연장보증)보험을 실제로 팔고 있습니다.
- 안전한 구조 세 가지:
  1. **검수 오류 환불형**: "검수서와 다른 상태였다면 플랫폼이 환불·회수한다." 이것은 우리 검수 서비스의 품질 보증이지 위험 인수가 아니라 보험 쟁점이 작습니다. **권장.**
  2. **판매자 하자담보 + 플랫폼 중재**: 보증 주체는 판매자, 플랫폼은 분쟁 기준과 에스크로 보류로 집행.
  3. **보험사 제휴 EW**: 수리비까지 보장하려면 손해보험사와 제휴(롯데손보 EW 같은 상품)해 보험사가 보장하고 우리는 판매·검수만.
- 판정: **조건부**. 사이트 문구를 "공개된 기준에 따라 반품·수리를 보증"에서 "검수서와 다르면 환불, 수리 보장은 제휴 보험으로"로 좁히는 것을 권합니다. 법률 검토 1회 필요.

## 4. 결제: 카드 할부 · 네이버페이 · 카카오페이 · 토스 · 계좌이체 · 안전결제

- 기술: PG(토스페이먼츠·KG이니시스·나이스·NHN KCP, 또는 포트원 같은 통합사) 연동으로 카드·간편결제·계좌이체·가상계좌 모두 가능. 네이버페이·카카오페이·토스페이는 각각 별도 가맹 심사. 카드 할부는 신용카드만, 카드사 정책상 보통 5만 원 이상, 2~12개월, 무이자는 카드사 프로모션에 따름(체크카드 불가).
- 규제의 핵심: **플랫폼이 구매자 돈을 받았다가 개인 판매자에게 정산하면 전자금융거래법상 전자지급결제대행업(PG) 등록 대상**이라는 것이 금융위 보도설명자료를 인용한 업계 해석이며, 미등록 영업은 3년 이하 징역·2천만 원 이하 벌금 조항이 언급됩니다. 당근페이도 전자금융업 등록 후 안심결제를 시작했습니다(구매확정 후 지급, 구매자 2% 수수료). 번개장터(2018)·중고나라(2021)는 에스크로형 안전결제를 운영합니다.
- 선택지:
  1. **PG 지급대행 / 파트너 정산**: 돈이 플랫폼 계좌를 거치지 않고 PG가 보관했다가 구매확정 시 판매자에게 지급. 등록 없이 시작 가능한 구조로 업계에서 안내됩니다. **초기 권장.**
  2. **소규모 전자금융업 등록**: 분기 거래액 30억 원 이하로 운영하는 PG·결제대금예치업은 자본금 3억 원(2016년 완화). 일반 PG는 10억 원, 선불전자지급수단 발행업은 20억 원. 안심결제·포인트·지갑을 직접 하려면 이 길.
  3. 2025년 국회를 통과한 전자금융거래법 개정(PG 정의 명문화, 정산기한, 정산자금 외부관리·공시)은 PG와 정산 구조에 영향을 주므로 시행일·시행령을 확인해야 합니다.
- 에스크로 의무: 전자상거래법상 현금성 결제(계좌이체·가상계좌)는 구매안전서비스 적용 대상이고, 신용카드 결제는 예외입니다. C2C에서 통신판매업자는 개별 판매자이므로 플랫폼이 PG 에스크로를 제공하는 형태로 설계합니다.
- 세무: 2023-07부터 국세청장이 고시하는 전자게시판 사업자는 판매·결제대행·중개 자료를 제출해야 하고, 2024-05 국세청은 100여 플랫폼 자료로 반복 판매자에게 종합소득세 안내문을 보냈습니다(업계 추정 기준 연 50회·4,800만 원 이상). 우리 플랫폼도 고시 대상이 되면 분기 자료 제출 체계가 필요하고, 판매자에게 과세 가능성을 안내해야 합니다.
- 판정: **가능**. 사이트 문구는 유지해도 되지만, 상세 설계에 "초기에는 PG 지급대행, 규모가 커지면 전자금융업 등록"을 적는 것이 투자자 신뢰에 좋습니다.

## 5. 출장 리페어 · 보증 리페어맨

- 작업 범위: 출장으로 되는 것(셋업·현 교체·너트 교체·전장 수리·픽업 교체·잭/포트 교체·간단 프렛 레벨링), 공방이 필요한 것(프렛 교체·넥 리셋·도장·크랙 접착·바인딩). 사이트의 "공방이 필요한 작업은 픽업·반납"은 맞는 설계입니다.
- 공급: 한국의 기타 리페어는 개인 공방 중심이고 수가 적습니다. 수도권 한 권역(예: 홍대·합정·마포)에서 리페어맨 5~10명으로 시작해야 동선과 응답 시간이 나옵니다. 리페어맨은 보통 자기 공방 작업이 본업이라 "비는 시간 출장"으로 설계해야 합니다.
- 법·보험: 리페어맨은 프리랜서(3.3% 원천징수) 또는 사업자. 산재보험의 노무제공자 직종(2023-07 전속성 폐지, 18개 직종 + 2024 추가)에 악기 수리기사는 없으므로 상해보험·배상책임보험(작업 중 악기 파손)을 플랫폼이 묶어서 가입해야 합니다. 고객 집 방문이라 신원 확인·사진 기록도 필요합니다.
- 보증: 사이트가 "플랫폼이 수리 결과를 보증"이라고 쓰려면 **플랫폼이 수리 계약의 당사자(서비스 제공자)**여야 자기 서비스의 하자 보증이 됩니다. 단순 중개자가 제3자 보증을 유상으로 붙이면 3장과 같은 보험업법 쟁점이 생깁니다. 헤이딜러·엔카보증 비유는 "진단 + 보증"이라는 경험의 비유로만 쓰고, 같은 법적 구조라고는 쓰지 않습니다(엔카 워런티는 기간·한도·자기부담금이 있는 보증 프로그램으로 보도됐고, 보험사 제휴 여부는 미확인).
- 판정: **가능(구조 선택)**. "플랫폼이 계약 당사자 + 리페어맨이 수행 + 하자 보증 기간 명시" 구조를 권합니다.

## 6. 멤버십 라운지

- 가능합니다. 비용 통제가 전부입니다. "무료 출장 리페어"는 "연 2회 셋업 또는 현 교체, 출장비 면제, 수도권" 식으로 범위를 정해야 표시광고 문제가 없습니다. 월 구독은 전자상거래법 청약철회·환불 규정을 따르고, 연간 선납은 중도 해지 환불 기준(소비자분쟁해결기준)을 약관에 넣습니다.
- 라운지: 자체 공간은 고정비가 크므로 초기에는 제휴 공방·합주실의 시간대를 빌리는 "라운지 데이"로 시작합니다.
- 판정: **가능**.

## 7. 장비 이력부

- 가능하고, 이 사업에서 가장 복제하기 어려운 자산입니다. 어려움: 브랜드별 시리얼 규칙이 달라(펜더 US/MX/JP, 깁슨 9자리, PRS 등) 연식 추정 파서가 필요하고, 위조 시리얼·시리얼 없는 커스텀 악기가 있습니다. 소유자 이력은 가명 처리(개인정보보호법), 소유 이전은 양쪽 확인. 장물 조회는 공개 API가 없어 경찰청 신고 안내로 대체.
- 초기 데이터는 우리 거래·검수·수리 건에서만 쌓입니다. 외부 채널 매물은 이력부에 못 들어오므로(1장) "이력부가 붙은 매물 = 우리 장터 매물"이라는 차별점으로 쓰는 것이 맞습니다.
- 판정: **가능**.

## 8. 로디(AI) · 메신저 · 샵 운영 도구 · 파트너 허브

- 로디: 도구 호출형 LLM + 승인 카드 + 서버 권한 검사 + 감사 로그는 표준 패턴입니다. 주의: 고객 채팅·사진·판매글에 섞인 지시문(프롬프트 주입)을 명령으로 받지 않도록 "대화 내용은 데이터, 명령은 담당자만" 규칙을 코드로 강제합니다. 추론 비용은 대화당 과금이므로 조회·제안은 저가 모델, 실행 제안만 고성능 모델로 나눕니다.
- 메신저: 센드버드·톡플러스 같은 CPaaS 또는 Matrix 같은 오픈소스. 0.1초 전송 중 표시, 0.5초 대화방 열기, 95% 1초 도착, 중복 0건(멱등 키)은 달성 가능한 목표입니다. "관리자도 상시 열람 안 함"은 접근 통제 + 감사 로그 + 법적 요청 절차로 구현합니다.
- 샵 운영 도구: 접수·작업 기록·부품 재고·정산·보증 기간은 일반적인 업무 앱입니다. 기존 POS·회계(더존·이카운트) 연동은 초기엔 CSV 내보내기 정도로 둡니다. 세금계산서는 홈택스 연동 서비스(바로빌 등)로 가능합니다.
- 파트너 허브: 사업자 간 거래는 세금계산서·계좌이체가 기본이라 결제 규제 부담이 작습니다. 공동구매에서 플랫폼이 구매 주체가 되면 도소매업이 되므로 초기엔 중개로만.
- 판정: **가능**.
